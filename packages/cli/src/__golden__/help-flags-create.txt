frijoles flags create — create a flag, with a polarity, in the environments you name

Usage
  frijoles flags create <key> --kill-switch|--enablement --all-envs

Polarity decides whether the flag is born on or off, in every environment you name:

    --kill-switch   on  everywhere   (it is on until you kill it)
    --enablement    off everywhere   (you switch it on deliberately later)

  The flags page shows the same switch: on is on, off is off. Change it with
  `frijoles flags set <key> --value true|false` or `frijoles flags kill <key>`.

  For a non-boolean flag use --type with --variants and --default; polarity does not apply,
  because "which way is off?" has no answer for a string.

Flags
  --env <environment>   development | preview | production (repeatable)
  --all-envs            all three environments, under the partial-failure contract
  --project <slug>      the project (default: the remembered one)
  --reason <text>       why — it goes in the audit trail (default: "via frijoles")
  --kill-switch         born serving true — the incident switch
  --enablement          born serving false — the gate you open later
  --description <text>  what the flag is for
  --type <type>         string | number | json (omit for a boolean)
  --variants <json>     a JSON array of {key,value} — with --type
  --default <key>       which variant is served by default — with --type

Exit codes
  0  ok         it worked
  1  usage      the command is wrong — nothing was sent
  2  auth       the credential is not accepted — run `frijoles login`
  3  not-found  no such thing, or not yours
  4  conflict   someone else changed it — re-read and retry
  5  partial    some environments changed and some did not
  6  server     the server or the network is unwell — retry
