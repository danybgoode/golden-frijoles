# Pitch — the template scripts pass the consumers' gates before the copy-in does

Moves · Tests: neither — a chore. Why: keeps the plugin's shared scripts from breaking the projects that copy them.

**Consolidated 2026-10-14** from [`foundation-lint-gate`](foundation-lint-gate.md),
[`script-ismain-realpath`](script-ismain-realpath.md) and [`perf-probe-target-allowlist`](perf-probe-target-allowlist.md),
now archived. All three harden `skills/template/scripts`, each ends in a CI guard, and together they make one plugin
release (`skills/RELEASING.md`). It can share a release window with `build-view-one-story`.

## The ask, as given

> help me consolidate and streamline overall
> — Daniel, 2026-10-14 (the three chores, merged at his approval)

### Claims
1. The shared scripts pass the gates their consumers run.
2. They run when invoked through a symlinked path.
3. The smoke probe can't be pointed at an internal address.

**Teach-back:** yes — approved as one chore at the consolidation, 2026-10-14.

## Problem

- **Lint.** `eslint.config.mjs` ignores `skills/**` ("linting them is `foundation-lint-gate`'s job"). Consumers run
  `eslint --max-warnings=0` and Prettier on changed files, so unused bindings and unformatted files reached golden-beans
  twice (plugin waves 1 and 2: 13 orphaned bindings, then an unused import plus six unformatted files), each costing a
  fix PR and a `.prettierignore` entry downstream.
- **`isMain`.** 17 template scripts and 5 plugin scripts decide "was I run directly?" with
  `resolve(process.argv[1]) === fileURLToPath(import.meta.url)`. Under a symlinked path (macOS `/var` →
  `/private/var`, a symlinked checkout) that is false, and the script does nothing and exits 0. `config.mjs` and
  `render-ways-of-working.mjs` already compare realpaths.
- **perf-probe.** `perf-probe.mjs` checks only for an `http(s)` prefix on `baseUrl` and then follows the
  `/_next/static/…` URLs the HTML names. A PR editing `golden-frijoles.config.json → smoke.perf` could point a CI
  runner at `169.254.169.254` (raised by the security lens on miyagi-product-management#196).

## Scope

**In v1:** `no-unused-vars` (at least) over `skills/template/scripts` and the plugin's hooks in skills-ci with
`--max-warnings=0`; one decision on Prettier (below); `lib/is-main.mjs` (realpath on both sides) used by all 22
scripts, plus a CI guard failing on the lexical form; perf-probe refusing loopback, link-local and private ranges
unless the project opts in (`smoke.perf.allowPrivate: true`), and fetching assets only from `baseUrl`'s own origin,
with a test per refusal.
**Out of v1 (no-gos):** adopting the consumers' full ESLint config at the source; DNS-rebinding defence (the probe
resolves once; stated as a residual); this repo's own `scripts/` copies beyond what `check-script-parity` already
syncs.

## Rabbit holes

- **Prettier: format at the source, or have consumers ignore?** Consumers' Prettier configs differ, so formatting at
  the source with one config can still fail a consumer's check. Recommended (decision a): consumers ignore the vendored
  rails, and `frijoles-kit init` writes that one `.prettierignore` block, instead of one file at a time. Lint stays at
  the source either way. **Decided 2026-10-14 (Daniel): as recommended.**
- **A hostname that resolves to a private address.** Check the resolved address, not just the literal host, before
  each request.
- **22 files in two trees** plus this repo's copies: the parity check (`check-script-parity`) must stay green.

## Acceptance criteria

- **S1.1** (low): skills-ci fails on an unused binding in a template script (seeded in a spec fixture); `frijoles-kit
  init` writes the rails' `.prettierignore` block, idempotently.
- **S1.2** (low): `isMain(import.meta.url)` from `lib/is-main.mjs` in all 22 scripts; a test runs one through a
  symlinked directory and sees it act; a guard fails CI on the lexical form.
- **S1.3** (high, security lens): perf-probe refuses `127.0.0.1`, `169.254.169.254`, `10.0.0.1` and a hostname
  resolving to one, unless `allowPrivate`; refuses an asset URL on another origin; a test per refusal.
- QA: node tests in skills-ci; an interactive check by an agent in a scratch repo with a symlinked checkout.
